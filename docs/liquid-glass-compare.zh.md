# Liquid Glass 对照实验：Alaya 自研 vs `@xiaojiaenen/liquid-glass`

> 一句话：**开源组件的折射在本机环境里是真的在工作的，而且它的位移贴图比 Alaya 自研那份干净；
> 但直接套用它的组件不划算——代价在集成和帧时间上，不在光学上。真正压住观感的不是引擎，是 tint。**

本文只放可复现的实验与数字。材质规范见 `docs/liquid-glass.zh.md`，本文不重复令牌表。

| 产物 | 说明 |
| --- | --- |
| `tests/liquid-glass-compare.mjs` | 四引擎同环境对照：截图 + 像素量测 + 帧间隔 + 贴图成本 |
| `tests/liquid-glass-isolation.mjs` | 滤镜链逐节点隔离：哪一步真在位移、哪一步只是刷色 |
| `tests/fixtures/liquid-glass-compare/` | 对照页、隔离页、CDP 驱动、PNG 读写（无第三方依赖） |
| `test-tmp/liquid-glass-compare/`、`-gpu/` | 截图与 `metrics.json`（软件合成 / GPU 合成各一份） |
| `test-tmp/liquid-glass-isolation/`、`-gpu/` | 隔离实验截图与 `isolation.json` |

复现：

```powershell
Push-Location work\mistake-notebook-addon
node tests/liquid-glass-compare.mjs        # 软件合成（与验收脚本同口径）
node tests/liquid-glass-compare.mjs --gpu  # 换 GPU 合成再跑一遍
node tests/liquid-glass-isolation.mjs
Pop-Location
```

第三方包由脚本自动取：`@xiaojiaenen/liquid-glass@0.1.5`（MIT，peer react 18），放进
`test-tmp/liquid-glass-probe/`；React 18 UMD 一并装在那里（只为把它的 ESM dist 直接跑起来）。

## 1. 结论

1. **它没有坏。** 隔离实验里，第三方自己那条滤镜链在贴边产生的环差是 32.5（Alaya 式 28.0），
   对照「只做饱和度」13.4、「只叠镜面」5.3 —— 位移确实发生了。之前「路线相近所以问题可能一样」
   的推断不成立。
2. **它的位移贴图比 Alaya 自研那份干净。** 同底色同几何下，「边缘不稳」（沿边剖面相对中位剖面
   的 RMS）在 A = 5.95–8.95、B（自研折射）= 11.07–17.0、C2（开源对齐参数）= 1.0–6.06。
   A→B 只换了背景采样链路，不稳度翻 1.4–2.5 倍：**自研折射引入的那点「接缝感」是位移贴图带来的，
   不是 tint、不是模糊、也不是 backdrop-filter 本身。** C2 把同一件事换成它的滤镜链，不稳度反而降了。
3. **直接换不划算，代价在帧时间。** 每个引擎的 4 个面单独在场时（3 次 × 120 帧取中位）：
   GPU 合成下 Alaya 两条引擎都等于基线（6.9ms），开源两行是 **13.8ms，整整 2 倍**；
   软件合成下开源两行分别掉帧 36.7% / 65.8%，Alaya 是 0–3.3%。原因是每个面一张独立 SVG 滤镜 +
   两张 `feImage` + 一次 `feBlend`，逐帧重算。
4. **卡住观感的是 tint，不是引擎。** Alaya 的浮层面是 0.60–0.80 白，C2 用同一个位移引擎、只把
   tint 对齐到 0.70，材质强度 69.5 对 A 的 72.5 —— 折射在 0.7 的白底下几乎看不见。
   反过来开源默认 tint 0.03 又太透：材质强度只有 7.7–18.7，等于没着色。
5. **该拿的是它的光学推导，不是它的组件。** 贴图生成（轮廓函数 / 厚度 / 折射率 → 位移幅值）、
   尺寸精确生成、200% 滤镜区域、烘进滤镜的镜面层，这四样都值得搬；React 壳与滤镜组合不值得。

## 2. 方法：为什么这个对照算公平

四个引擎装在同一张页面上，**同一底层背景、同一几何、同一 Chromium**：

| 引擎 | 实现 | 备注 |
| --- | --- | --- |
| A `alaya-css` | `glass.css` 的既有基元（blur + saturate + brightness + tint + 斜面） | 发布形态 |
| B `alaya-refraction` | `glass-refraction.js` 实验档（法线贴图 + `feDisplacementMap`），接管 `backdrop-filter` | band 14 / scale 30 / 16px 分桶 |
| C1 `xiaojiaenen-default` | 原版组件默认参数（tint .03、backdropBlur 0、按其 preset） | 真跑 dist，不重写 |
| C2 `xiaojiaenen-aligned` | 原版组件，tint .70 + backdropBlur 20 + saturate 1.75 | 对齐 Alaya 的观感前提 |

四个面：`1180×72 r0`、`420×260 r16`、`168×44 r8`、`132×40 r999`（圆角是**强制**的：Alaya 现行设计
把玻璃面写成直角，圆角是裁剪与接缝最容易暴露问题的形状，把它排除掉等于不测）。

底层背景是**按周期平铺**的：1px 白网格（12px 周期，位移/接缝的敏感探针）+ 高饱和色环（160px）
+ 明暗带（64px）。四行采样到的底层结构因此是等价的，跨引擎比较才有意义。

两种截图口径：

- **观感档**（`compare.png`）：带文字、带投影，给人看。
- **量测档**（`compare-clean.png`）：藏文字、掐投影。文字的白字二阶差分比接缝大两个数量级；
  投影是设计令牌而不是光学路径，落在圆角外不等于「裁剪失效」。**所有数字都出自量测档。**

量测全部在**合成后的像素**上做，不对 DOM 里的 `backdrop-filter` 取值下判断——那正是
「能跑但不可靠」最容易骗过自己的地方。

| 指标 | 定义 | 读法 |
| --- | --- | --- |
| 材质强度 | 面内（内缩 4px）与「无玻璃基准」的平均差 | 面改动了多少背景 |
| 边缘/中心 | 贴边带差 ÷ 中心差 | >1 说明效果集中在边缘（折射），≈1 说明全幅（模糊/刷色） |
| 边缘不稳 | 沿边取剖面、与中位剖面比较的 RMS | 位移贴图被拉伸/圆角对不上时变大 |
| 接缝 p90 | 沿边内 2–20px 的二阶差分 p90 | 与边平行的硬跳变 |
| 圆角外泄 / 面外 | 圆角弧线外、面外 6px 环 与基准的差 | 裁剪/位移越界的泄漏量 |
| 滚动差 | 背景上移 60px 后面内的变化 | ≈0 说明贴死了一张旧图 |

### 3.1 材质指纹

| --- | --- | --- | --- | --- | --- | --- | --- |
| alaya-css | bar 1180×72 | 60.8 | 1.07 | 6.71 | 5.9 | 28.9 | — |
| alaya-css | float 420×260 | 72.5 | 1.08 | 8.95 | 3.9 | 21.1 | 0/0 |
| alaya-css | control 168×44 | 69.6 | 0.99 | 8.08 | 3.0 | 33.7 | 0/0 |
| alaya-css | pill 132×40 | 56.5 | 1.01 | 5.95 | 68.9 | 25.9 | 0/0 |
| alaya-refraction | bar | 66.8 | 0.93 | **17.00** | 115.8 | 22.1 | — |
| alaya-refraction | float | 66.6 | 0.93 | **12.15** | 92.2 | 19.1 | 0/0 |
| alaya-refraction | control | 53.2 | 0.98 | **16.03** | 98.6 | 25.6 | 0/0 |

| xiaojiaenen-default | bar | 7.7 | 1.21 | 46.5 | 245.4 | 70.1 | — |
| xiaojiaenen-default | float | 14.5 | 3.15 | 50.7 | 252.5 | 66.3 | 0/0 |

| xiaojiaenen-aligned | control | 63.9 | 0.99 | 5.32 | 2.8 | 12.0 | 0/0 |
| xiaojiaenen-aligned | pill | 78.8 | 0.95 | 1.11 | 82.8 | 13.4 | 0/0 |

怎么读：

- **A → B**：同 tint、同几何、同边框，只换背景采样链路。材质强度几乎不变（72.5→66.6），
  但边缘不稳 8.95→12.15（bar 6.71→17.0）、接缝 p90 3.9→92.2。**这就是「自研折射有接缝感」的量化证据，
  归因明确：位移贴图。**
- **C2**：同样的位移引擎，参数对齐后边缘不稳 1.0–6.1、接缝 p90 1.1–1.4（pill 例外，见下），
  比 A 还干净。**它的位移贴图没有引入不稳。**
- **C1**：材质强度只有 7.7–18.7——tint 0.03 撑不起材质，看上就是「几乎没玻璃」；它的不稳度
  （25–51）主要来自烘进滤镜的镜面亮线沿边不均匀，不是接缝（接缝 p90 高是因为那条亮线的二阶差分）。
- **pill 的接缝 p90 在 A（68.9）和 C2（84.0）都不低**：胶囊半径 999 → 实际 20px，贴图按整圆生成，
  与「圆角矩形」的边中段几何不同，这一段本来就不该用矩形边中段的二阶差分去判。两项都是小面，
  不作为结论依据。

### 3.2 帧间隔（每个引擎 4 个面单独在场，3 次 × 120 帧取中位）

| 引擎 | 软件 p50 | 软件 p95 | 软件掉帧 | GPU p50 | GPU 掉帧 |
| --- | --- | --- | --- | --- | --- |
| 无玻璃 | 16.7 | 16.8 | 0% | 6.9 | 0% |
| alaya-css | 16.7 | 16.8 | 3.3% | 6.9 | 0% |
| alaya-refraction | 16.7 | 16.7 | 0% | 6.9 | 0% |
| xiaojiaenen-default | 16.7 | 33.4 | 36.7% | 13.8 | 0.8% |
| xiaojiaenen-aligned | 33.3 | 50.1 | 65.8% | 13.8 | 0% |

**环境限制（重要）**：两次运行都报 `ANGLE (Microsoft, Microsoft Basic Render Driver (0x0000008C) Direct3D11)`
——包括 `--gpu` 那次。也就是说两份数字都是**软件栅格化**（第二次没加 `--disable-gpu`，帧间隔被
vsync 压成 6.9ms 基线）。**只能相对比较，不能当真实 GPU 帧率用。** 本机 `electron.exe` 起不来
（`0xC0000005`，见主文档 §7.4），真机帧率与显存占用仍未测。

不过两套运行给出一致的相对关系，这点反而比绝对值有用：**Alaya 的两条引擎都等于基线，
开源那套是基线的 2 倍帧时间**（软件路径下直接体现为掉帧 37–66%）。Alaya 自研折射最便宜——
它不开 blur，只有一次位移。

### 3.3 位移贴图成本（每尺寸一次，软件合成）

| 面 | 第三方 ms（2 张图） | 第三方字节 | Alaya 循环 ms | Alaya 编码 ms | Alaya 字节（1 张图） |
| --- | --- | --- | --- | --- | --- |
| bar 1180×72 | 4.7 | 5520 | 9.5 | 8.9 | 3970 |
| float 420×260 | 7.1 | 13136 | 11.1 | 11.9 | 6374 |
| control 168×44 | 0.9 | 2544 | 1.7 | 1.6 | 1738 |
| pill 132×40 | 1.1 | 5012 | 1.0 | 1.0 | 2758 |

要点：

- 第三方**按元素精确尺寸生成**（`Math.round(rect.width/height)`，100ms 防抖），两张图（位移 + 镜面）；
  Alaya 按 **16px 分桶**、最多 8 张，420×260 实际用 416×256 拉伸 → 约 1% 的几何误差。
- 两边的生成耗时同量级（第三方一张图更省，因为它用 typed array 内循环；Alaya 每像素分配对象，
  但要生成的数据量也不同）。真正的差别不在这里，而在 §3.2 的逐帧重算成本。

## 4. 隔离实验：哪一步真在位移

`tests/liquid-glass-isolation.mjs`：用**第三方自己的贴图生成器**造贴图，把它的滤镜链按节点拆成 15 个
变体，每格同尺寸（420×240 r20）铺在同一张网格底上；再关掉全部滤镜截基准图，逐格量
**环差**（贴边 0–8px）与**内部差**（离边 14px 以内）。

判据：「位移」只发生在贴边那条带里（贴图中心是中性值 128），所以位移指纹是
**环差高 + 内部低**（带内比大）；blur 与饱和度是全幅效果（带内比 ≈ 1）。

| 变体 | 环差 | 内部差 | 带内比 | 判定 |
| --- | --- | --- | --- | --- |
| V1 `feImage→feDisplacementMap`（Alaya 式） | 28.0 | 1.9 | 14.6 | 位移 |
| V2 链首加 `feGaussianBlur(.5)` | 18.9 | 1.7 | 11.2 | 位移 |
| V3 同 V2，滤镜区域 -50%/200% | 43.0 | 1.9 | 22.4 | 位移（更强） |
| V4 第三方原链（模糊+位移+饱和+镜面），区域 -50%/200% | 32.5 | 14.8 | 2.2 | 位移 + 饱和 |
| V5 同 V4，区域改 100% | 25.0 | 14.5 | 1.7 | 位移 + 饱和 |
| V6 只 `blur(20px)` | 43.1 | 42.8 | 1.0 | 全幅 |
| V7 只 `feGaussianBlur(.5)` | 0.3 | 1.3 | 0.2 | 几乎为 0 |
| V8 有链首 blur，位移取 `SourceGraphic` | 24.6 | 2.6 | 9.6 | 位移 |
| V9 链首 `feGaussianBlur(0)` + 位移 | 46.2 | 2.3 | 20.4 | 位移 |
| V10 位移 + 镜面 screen | 31.3 | 2.2 | 14.3 | 位移 |
| V11 位移 + 饱和 | 29.8 | 14.8 | 2.0 | 位移 + 饱和 |
| V12 原链删掉链首 blur | 51.6 | 15.1 | 3.4 | 位移 + 饱和 |
| V13 位移后置 `feGaussianBlur(2)` | 30.7 | 24.8 | 1.2 | 位移 + 模糊 |
| V14 对照：只 `feColorMatrix` 饱和 | 13.4 | 13.3 | 1.0 | 全幅 |
| V15 对照：只镜面 + screen | 5.3 | 1.3 | 4.2 | 只有一条贴边亮线 |

（GPU 合成那一份的数字与上表逐项相差 <2，结论相同。）

由此成立的三件事：

1. **链首的 `feGaussianBlur` 不是阻断因素**（V2/V8/V9 都有位移）。我中途只看截图时曾误判
   「加了预模糊整个 backdrop-filter 就失效」，像素量测推翻了它——记在这里当方法学教训：
   **镜面亮线和位移在 1x 截图里长得一样，不能靠眼睛判。**
2. **滤镜区域影响强度**：V3（200%）43.0 vs V2（100%）18.9。Alaya 现在写的是 `0/0/100%/100%`，
   位移在元素边界处会被裁掉一截，这正是「贴边被拉平」的成因之一。
3. **`feImage` 只能吃 `data:` URI**（既有的结论在隔离实验里再次成立：换外部路径一律不画）。

## 5. 集成缺口：为什么「直接套用 36 个组件」不划算

实测（不是读 README 推断）：

1. **`styles` 入口是坏的。** `package.json` 的 `exports["./styles"]` 指向 `./dist/index.css`，
   而包里实际文件是 `dist/style.css`。`import '@xiaojiaenen/liquid-glass/styles'` 会 404，
   组件拿不到自己的 tint/描边/焦点样式。本轮对照页是手工引入 `dist/style.css` 才跑起来的。
2. **peer 依赖 React 18。** Alaya 渲染层是原生 ESM + 无框架（`app.js` / `index.html`）。
   要么引 React（UMD 约 140KB 起步，还要一个 root），要么把它的逻辑重写成 vanilla——后者就是自研。
3. **回退门是 UA 判断，不是能力判断**：`capabilities.js` 要求 `Chrome|Chromium|Edg` 且非 Safari 才走玻璃，
   其余一律 `is-fallback`（blur 4px + 噪声纹理）。Alaya 的三级分级（`resolveTier`）比它讲究，
   这一层应当保留 Alaya 的。
4. **接管点不对齐。** Alaya 的 chrome 面（`.side` / `.bar` / `.drawer`）把玻璃画在 **`::after`** 上，
   元素本身的 `backdrop-filter` 被显式置成 `none`（`glass.css` 245–278 行；`--glass-gutter: 10px`，
   `::after` 的 `inset: 8px 10px`）。任何「往元素上写 `backdrop-filter`」的引擎都接管不了这类面
   ——这不是参数问题。实测快照见 `metrics.json → facts.chromeSlot`。
5. **它的组件隐含「单 React root」**：`useId()` 在多个 root 里会各自从 `r0` 重新编号，让 filter id
   撞车（重复 id 会让 `url(#id)` 指到别人的贴图）。我第一次按「每格一个 root」挂载，8 个组件只剩
   4 个可用滤镜。改成单 root 后正常（`facts.thirdParty.filters` 有 8 个互不相同的 id）。

## 6. 圆角裁剪与「之前的问题」是否复现

8 倍放大的圆角截片（`test-tmp/liquid-glass-compare/crops/corner-*.png`）与数值都显示：
**四个引擎的圆角都按 `border-radius` 裁掉了**。量测档里「圆角弧线外的像素与无玻璃基准的差」
是 **0/0**（四个面全部为 0，逐面见表 §3.1），面外 6px 环同样是 **0/0**，边缘只有 1–2px 抗锯齿。

因此：

- `docs/liquid-glass.zh.md` §7.1 里「圆角裁剪失效、四角方角毛边」那条，**在本轮四引擎上没有复现**。
  原始 probe 目录 `test-tmp/glass-probe/` 现在为空（`probe3/probe4.png` 已不在），无法逐图对照。
- 这条不能再作为「拒绝 `url()` 折射」的理由；反过来，它也不能证明 `url()` 折射没有问题
  ——真机 Electron 窗口（高 DPI、多显示器、合成器路径不同）仍未测。
- 唯一能站住的说法是更窄的那条：**自研那份位移贴图沿边不一致**（边缘不稳 12–17 vs 6–9），
  换成第三方的贴图后消失（1–6）。

> 量测口径上的一个坑，写下来免得下次再犯：圆角外泄必须**按每个角各自的「外侧象限」**取像素
> （左上取 x<cx 且 y<cy，右上反过来）。四个角都按左上那种取法，会把另外三个角量的其实是
> **形状内部**，数字会虚高一个数量级（我第一版就是这样，得到 48–58 的假泄漏）。

## 7. 建议

1. **不换引擎**（0.7.24 之内）：现有 CSS 引擎 + 自研折射实验档的结构不改。
2. **把自研折射的贴图换成第三方的推导**：轮廓函数（`convex_squircle` 一类四次曲线）→ 法线 →
   位移幅值随厚度/折射率收敛；按元素**精确尺寸**生成（丢掉 16px 分桶）或至少在滤镜里改用
   `preserveAspectRatio` 之外的办法保证 1:1；滤镜区域改 `-50%/200%`；把镜面层烘进滤镜
   （`feImage` + `feBlend screen`），替代现在的 CSS inset 阴影。预期：边缘不稳 12–17 → 6 以下。
3. **要折射可感知，先改 tint**：浮层 0.80→0.60 的白把位移压得看不见（C2 与 A 的材质强度 69.5 vs 72.5）。
   想让光学起作用，浮层 tint 得降到 0.35–0.45 一档，并用描边/斜面补回层次——这一步的收益比换引擎大。
4. **只有在需要 36 个现成组件时**才考虑局部挂 React（例如设置面板），并且必须自己补两件事：
   `dist/style.css` 的引入、以及 chrome 面的 `::after` 接管（否则侧栏和顶栏不会跟着变）。
5. **分级与无障碍层保留 Alaya 的**：它的 UA 门不如 `resolveTier()` 的「强制色 > 高对比 >
   减少透明 > 用户选择 > 能力」这套顺序。
